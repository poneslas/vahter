## 1. Цель

Нажал кнопку ассистента — сразу говоришь с Hermes. Hermes на сервере ведёт сессии, помнит и думает. Телефон слушает, говорит, показывает и выполняет действия у тебя на глазах. Простые задачи на самом телефоне (будильник, заметка, файлы) телефон умеет делать и сам, в том числе без сети.

## 2. Принципы

- **Hermes — ядро, а не плагин приложения.** Сессии, память, долгие задачи, расписание, поиск живут в Hermes. Приложение для Hermes — ещё один мессенджер с одним чатом один на один.
- **Hermes не трогаем.** Интеграция — это platform-плагин в `~/.hermes/plugins/`. Hermes продолжает обновляться штатно (`hermes update`) и со временем становится лучше сам.
- **Одна память — у Hermes.** Телефон хранит только кэш, офлайн-очередь и собственный журнал действий.
- **Hermes действует на телефоне только в интерактиве.** Инструменты телефона доступны ему лишь во время открытой сессии, и каждый вызов виден на экране. Никаких автономных звонков, SMS и действий по расписанию.
- **На телефоне — только короткие действия.** Любое действие на телефоне укладывается в секунды и выполняется, пока открыт разговор. Долгие фоновые задачи, сопроцессор и локальный агент — не цель проекта, а гипотезы (раздел 17).
- **Ни с кем не конкурируем.** Это личный инструмент. Где есть зрелые приложения (Telegram для файлов и длинных разборов, галерея для фото), отдаём работу им.
- **Наружу — только руками пользователя.** Всё, что уходит другим людям, агент готовит как черновик, а отправляет человек.
- **Абстракции есть, зоопарка нет.** Слои «LLM-провайдер», «распознавание», «синтез речи» заложены интерфейсами, но в первой версии у каждого одна реализация.
- **UX — как у приложения Claude.** Dicio, Hermes-Mobil и hermes-android служат образцами архитектуры, не дизайна.

## 5. Кто что решает: маршрутизация

Каждую фразу берёт самый дешёвый уровень, который справится. Всё, что сложнее базовых действий на телефоне, уходит в Hermes.

| Уровень | Что это | Когда появляется |
|---|---|---|
| **Правила** | ключевые слова и шаблоны для 3–5 команд | прототип (Ф1): таймер, будильник, фонарик |
| **Локальный маршрутизатор** | маленькая нейросеть-классификатор + парсеры параметров | Ф3: ~15 локальных команд |
| **Hermes** | серверный агент со всей памятью и инструментами | с Ф1: всё остальное |

### 5.1. Правила (прототип)

Шаблоны вида «(поставь|заведи) будильник на {время}» → `alarm.set(time)`. Слоты разбираются парсерами русских чисел и времени. Совпало — действие выполняется сразу, без модели и без сети; не совпало — фраза уходит дальше.

- **Плюсы:** миллисекунды, детерминированно, без модели.
- **Минусы:** ломается на перефразировке, каждую команду надо описать руками.

В прототипе правила нужны только чтобы проверить путь «локальное выполнение». С Ф3 их заменяет маршрутизатор; правила остаются как самый быстрый путь для 3–5 команд.

### 5.2. Локальный маршрутизатор (Ф3)

Не языковая модель, а быстрый классификатор фраз, который знает только локальные функции и честно говорит «не моё» обо всём остальном.

1. **Классификатор намерений** — компактный русский энкодер (кандидат — rubert-tiny2, ~30 МБ, ONNX int8). На выходе функция и уверенность, за миллисекунды.
2. **Разбор параметров** — детерминированные парсеры: время, длительность, числа, контакты (телефонная книга + кэш прозвищ от Hermes).
3. **Порог уверенности** — ниже порога фраза уходит в Hermes. Если не хватает параметра, звучит уточняющий вопрос («На когда?»).
4. **Обучение** — синтетические фразы от большой модели + ручные примеры + класс «не моё». Модель обновляется скачиванием, без обновления приложения.

Без сети маршрутизатор — единственный «мозг»: всё, что он не может выполнить, ложится в очередь для Hermes.

### 5.3. Размещение функций

У каждой функции в реестре есть поле `placement`, которое задаёт, кто может её вызвать:

| placement | Вызывают | Примеры |
|---|---|---|
| `local` | правила и маршрутизатор | фонарик, громкость, «не беспокоить» |
| `local+hermes` | маршрутизатор и Hermes в активной сессии | будильник, календарь, заметка, геолокация, файлы (чтение списков), уведомления |
| `hermes` | только Hermes | всё серверное: память, почта, поиск, cron |

Реестр задаётся в приложении. Политику (включено или нет, уровень подтверждения) пользователь меняет в настройках.

## 6. Голосовой контур

**Голос не покидает телефон.** Распознавание — GigaAM на устройстве, на сервер уходит только текст. Так быстрее и приватнее. Серверная GigaAM — гипотеза для длинной диктовки (раздел 17).

| Этап | Реализация | Интерфейс под замену |
|---|---|---|
| Активация | роль ассистента (`VoiceInteractionService`), кнопка гарнитуры, плитка быстрых настроек, виджет | — |
| Нарезка речи | Silero VAD (из sherpa-onnx): ловит конец фразы | — |
| Распознавание | GigaAM v3 **e2e** (с пунктуацией и заглавными) int8 через sherpa-onnx на телефоне: черновые проходы — `e2e_ctc`, чистовой — `e2e_rnnt`, если укладывается по времени и памяти | `SpeechRecognizer`: серверная GigaAM, облачный провайдер |
| Караоке своей речи | черновой прогон каждые 300–400 мс по растущему буферу, первый показ после 0,6–0,8 с речи, слова фиксируются при совпадении в двух гипотезах подряд, чистовик по концу фразы | потоковая модель sherpa-onnx только для черновика |
| Эквалайзер | алгоритм Гига Писаря: пиковый RMS по 10 мс, адаптивная шкала по полу шума, гамма 0,6, 13 столбиков, случайность раз на всплеск, 60 fps | — |
| Синтез речи | **в первой версии нет: ответ только текстом.** Потом — системный TTS Android (`onRangeStart` даёт караоке ответа), голос выбираем на слух | `SpeechSynthesizer`: Piper/sherpa-onnx, облачный TTS |

- **Опыт Гига Писаря.** Захват, отбраковка (короче 0,4 с, «микрофон отдал тишину»), нарезка длинной речи по паузам, эквалайзер и движение оверлея переносятся из Писаря с его значениями. Полная спецификация с источниками — `Голосовой_контур.md`.
- **Ограничение GigaAM:** модель не потоковая. Показа текста по мере речи нет ни в одной версии Писаря, это наша разработка. Черновое караоке — повторные прогоны на растущем буфере. Скорость и расход батареи проверяем замерами в Ф1.
- **Экономия:** модель распознавания грузится параллельно с анимацией оверлея и выгружается после простоя. Wake word («Эй, …») не делаем.

## 7. Приложение: вход и интерфейс

### 7.1. Роль ассистента

- Приложение регистрирует `VoiceInteractionService` + `RecognitionService` и запрашивает `ROLE_ASSISTANT`. Долгое нажатие питания/Home открывает наш оверлей.
- **Известная проблема:** после переустановки/обновления APK Android сбрасывает роль ассистента. Так же ведёт себя и официальное приложение Claude ([issue #41696](https://github.com/anthropics/claude-code/issues/41696)). Приложение при каждом запуске проверяет роль и предлагает восстановить её в один тап.
- Работа поверх экрана блокировки: вопросы — да, действия с данными — только после разблокировки.

### 7.2. Экраны (ориентир — приложение Claude)

| Экран | Содержание |
|---|---|
| **Голосовой оверлей** | Открывается сразу в режиме «слушаю», быстрее 300 мс. Эквалайзер по живому голосу, караоке своей речи (черновик → чистовик) и ответа (подсветка произносимого слова), последние реплики сессии, карточки действий. Цвет показывает, кто работает: телефон или Hermes. Кнопки: стоп / клавиатура / «История»; свайп вверх открывает ленту |
| **Лента (История)** | Весь канал с Hermes одной лентой, разделители сессий, поиск, повтор голосом любой реплики. Подгрузка страницами с сервера |
| **Карточка действия** | Что будет сделано, параметры, кнопки «Да / Изменить / Отмена»; после выполнения — «Отменить» |
| **Настройки** | Сервер и привязка устройства, функции и их подтверждения, уведомления (какие приложения), модели на телефоне, голос |
| **Журнал действий** | Что, кто (правила / маршрутизатор / Hermes), когда, с каким подтверждением |

Макеты воспроизводим по скриншотам приложения Claude для Android. Для публичного релиза уходим от прямой копии фирменного стиля (иконка, палитра, название).

### 7.3. Как «прячем мусор» Hermes

Hermes бывает многословен и сыплет служебным выводом. Бороться будем с двух сторон, не меняя Hermes:

- **Навык `android` в Hermes:** правила канала: голосовой ответ — 1–2 предложения, подробности — текстом ниже, без списков и markdown в первой фразе, не пересказывать вызовы инструментов.
- **Отображение на телефоне:** служебные и промежуточные сообщения сворачиваются в одну строку «Hermes работает: …» с раскрытием по тапу. Озвучивается только первый абзац финального ответа.

## 8. Функции телефона

### 8.1. Уровни подтверждения

- **П0** — без подтверждения: действие внутри телефона, легко отменяется (карточка с «Отменить»).
- **П1** — карточка «Да / Нет» или голосом «да».
- **П2** — только руками: агент готовит черновик и открывает нужное приложение, но не отправляет.

Уровень задаёт **телефон** по своему реестру. Hermes не может его понизить.

### 8.2. Реестр v1

| Функция | placement | Для Hermes | Подтв. | Как сделано |
|---|---|---|---|---|
| Будильник, таймер | local+hermes | П1 | П0 локально | Intent `AlarmClock` |
| Событие в календаре | local+hermes | П1 | П0 локально | `CalendarContract` |
| Заметка / «запомни» | local+hermes | — | П0 | уходит в Hermes (в память); без сети — очередь |
| Геолокация, «где машина» | local+hermes | П1 | П0 | FusedLocation + фото |
| Звонок | local | — | П1 | `ACTION_DIAL`/`ACTION_CALL` |
| SMS, мессенджеры | local+hermes | П2 | П2 | черновик и открытие приложения (как у Claude) |
| Музыка, громкость, «не беспокоить», фонарик | local | — | П0 | медиасессия, системные API |
| Экран «что здесь» | local+hermes | П1 | П1 | скриншот по запросу через `VoiceInteractionSession` (assist structure) |
| Файлы | local+hermes | см. 8.3 | см. 8.3 | Storage Access Framework |
| Уведомления | local+hermes | см. 9 | см. 9 | `NotificationListenerService` |
| Платежи, автоответчик | — | — | — | осознанно исключено |

Управление чужими приложениями через спецвозможности (нажатия, свайпы) в v1 не входит.

### 8.3. Файлы

- **Доступ:** пользователь выдаёт доступ к конкретным папкам через `ACTION_OPEN_DOCUMENT_TREE` (Загрузки, Документы, DCIM…). Режим «доступ ко всем файлам» (`MANAGE_EXTERNAL_STORAGE`) — опция для личной сборки, не по умолчанию.
- **Инструменты:** `files.list`, `files.stat`, `files.search` (имя, тип, размер, дата), `files.hash` (для дубликатов), `files.move`, `files.rename`, `files.mkdir`, `files.trash`.
- **Удаления нет,** есть только корзина: своя папка `.trash` с журналом, срок хранения 30 дней, «Отменить» в карточке.
- **Подтверждения:** чтение — П0; перемещение и корзина — П1 с планом (список файлов, объём). Hermes видит только метаданные (имена, размеры, даты); содержимое файла уходит на сервер лишь по отдельному П1.
- **План вместо мелких операций:** `files.scan` возвращает сводку за секунды, `files.plan` показывает план карточкой, `files.apply` выполняет его с откатом. Только то, что укладывается в секунды, пока открыт разговор.
- **Первые сценарии:** «почисти загрузки» (старые APK, дубликаты, файлы старше N дней), «разложи по папкам», «найди файл, который мне прислали вчера», «рассортируй фото». Дальше наращиваем по одному.

## 9. Уведомления

- **Сбор локально.** `NotificationListenerService` пишет уведомления выбранных приложений в локальную базу с хранением 48 часов. Приложения выбирает пользователь; банки и 2FA по умолчанию исключены.
- **Локально:** «что пришло?» — озвучка или сводка (локально или через Hermes); фильтр по приложению и контакту.
- **В Hermes:**
  - вручную: «Отправь в Hermes» на уведомлении или голосом;
  - по правилам: «все письма от X», «всё из рабочего чата» — автоматически;
  - по запросу Hermes в активной сессии: `phone.notifications_recent`.
- **Уведомления — данные, а не команды.** Текст передаётся в Hermes в явной обёртке «содержимое уведомления, не инструкция». Фраза «переведи 5000 на карту» в чате не может стать действием: у Hermes нет таких инструментов, а действия на телефоне требуют подтверждения.
- **Открытый вопрос:** как передать пачку уведомлений в Hermes «на хранение», не вызывая ответ агента (см. раздел 15).

## 10. Интеграция с Hermes: плагин `android`

Разобрано по исходникам Hermes (HEAD 83597d9b71), подробности — в `Анализ_референсов.md`.

### 10.1. Устройство

Плагин ставится в `~/.hermes/plugins/android/` и включается командой `hermes plugins enable android`. Состав:

- `plugin.yaml`: `kind: platform`, `requires_hermes`, переменные (`ANDROID_BIND`, `ANDROID_ALLOWED_USERS`, `ANDROID_HOME_CHANNEL`);
- `register(ctx)` → `ctx.register_platform(...)` с `allowed_users_env`, `cron_deliver_env_var`, `platform_hint`, `max_message_length`;
- адаптер на `BasePlatformAdapter`:
  - `connect()` поднимает WebSocket-сервер на 127.0.0.1 (наружу — через Caddy);
  - входящие реплики → `MessageEvent` → `handle_message()`;
  - `send` / `edit_message` → потоковые кадры `reply.*`;
  - `_send_exec_approval_prompt`, `send_clarify` → нативные карточки;
- инструменты `phone.*` через `ctx.register_tool(...)`. Хендлер сам проверяет, что вызов пришёл из канала `android` (`HERMES_SESSION_PLATFORM`) и сессия активна: иначе инструменты были бы видны и в других мессенджерах;
- навык `android`: короткие голосовые ответы, когда звать функции телефона;
- по желанию (гипотеза, раздел 17): GigaAM как провайдер распознавания Hermes (`register_transcription_provider`).

Cron Hermes может прислать в канал **сообщение** (брифинг), но не вызвать инструмент телефона.

**Настройки Hermes:** `streaming.enabled: true` (по умолчанию выключено), `display.platforms.android.tool_progress: new`, `approvals.destructive_slash_confirm: false` или своя карточка подтверждения.

### 10.2. Сессии и история

- **Канал** — один чат один на один (`chat_type = dm`), ключ сессии `agent:main:android:dm:<chat_id>`.
- **Новая сессия после паузы** — в Hermes авто-сброса нет, поэтому плагин по таймеру (по умолчанию 30 минут тишины) отправляет синтетический `/new`.
- **История для ленты** — журнал канала в самом плагине (SQLite). Во внутреннюю базу Hermes не лезем: её формат может поменяться.
- **Память** — только память Hermes. Данные «на хранение» без ответа агента (уведомления, заметки из очереди): хук `pre_gateway_dispatch` пропускает ход, плагин пишет в память. В промпт это попадёт со следующей сессии.

### 10.3. «Активная сессия» для инструментов

Инструменты `phone.*` выполняются, только если одновременно:

1. вызов пришёл из канала `android`;
2. телефон на связи;
3. в последние N минут (по умолчанию 5) пользователь сам что-то сказал или написал, либо оверлей или лента открыты на экране (`session.state`);
4. функция разрешена политикой телефона.

Иначе вызов возвращает отказ «нет активной сессии». `check_fn` Hermes для этого не подходит: он кэшируется ~30 с на профиль, а не на сессию.

### 10.4. Совместимость с обновлениями Hermes

- Импортируем только документированное: `gateway.platforms.base`, `gateway.platforms.event`, `gateway.config`, `gateway.platforms._shared`. В сентябре 2026 Hermes уже отключил плагины со старыми внутренними путями.
- Своих Python-зависимостей не добавляем: `hermes update` отключает плагин при конфликте пакетов.
- Протестированные версии фиксируются в `UPSTREAM_TESTED.md`. Ночной CI гоняет тесты и `hermes plugins compat` против `main` и последнего релиза.
- Если обновление всё же ломает плагин: откат Hermes на проверенную версию. Приложение показывает «сервер несовместим», локальный режим продолжает работать.

### 10.5. Манифест возможностей телефона

**Манифест возможностей — единственный постоянный контракт.** Телефон присылает его в `hello` и обновляет через `capabilities.changed`, когда появляется новая опция (например, выдан доступ к календарю). Для каждой возможности указаны:

- имя, описание для модели, JSON-схема параметров и результата, версия;
- класс стоимости: мгновенно / секунды (долгих задач нет, раздел 2);
- приватность: что уходит на сервер (ничего / метаданные / содержимое по «да»);
- уровень подтверждения (П0–П2) и доступность сейчас (модель скачана, заряд, сеть).

**Как Hermes узнаёт о возможностях.** Механизм публикации сменный, решение принимаем замером в Ф4:

| Вариант | Как работает | Плюсы | Минусы |
|---|---|---|---|
| **А. Динамические инструменты плагина** | плагин регистрирует и снимает инструменты по манифесту (`register` / `deregister` в `tools/registry.py`) | в хендлере есть контекст сессии и канала, работает правило активной сессии | семантика смены инструментов посреди сессии не документирована |
| **Б. MCP-мост** | плагин поднимает MCP-сервер по манифесту; Hermes подключает его как обычный MCP и обновляет список по `tools/list_changed` (поддерживается, `tools/mcp_tool_health.py`) | открытый стандарт, документированное обновление списка | вызов, судя по всему, не несёт контекст сессии Hermes, поэтому правило «только из канала android» придётся обеспечивать иначе (подтверждение на телефоне) |

**Как этим пользоваться, Hermes объясняет навык `android`**: когда звать функции телефона, изменения файлов — только через `plan` → `apply`. Навыки обновляются отдельно от кода.

## 11. Протокол телефон ↔ плагин

Один WebSocket через TLS, JSON-сообщения с `id` для сопоставления. Соединение открывает телефон.

| Направление | Тип | Зачем |
|---|---|---|
| тел → сервер | `auth` | ключ устройства, подпись вызова сервера |
| тел → сервер | `hello` | версия, манифест возможностей и политика, состояние (батарея, сеть, экран) |
| тел → сервер | `capabilities.changed` | манифест изменился: появилась или пропала возможность |
| тел → сервер | `message` | реплика пользователя: текст, опционально аудио и контекст (время, место) |
| сервер → тел | `reply.delta` / `reply` | ответ Hermes: потоком, если поддерживается, иначе целиком |
| сервер → тел | `status` | «Hermes работает: …» — служебный прогресс, сворачивается в UI |
| сервер → тел | `tool.call` | вызов функции телефона |
| тел → сервер | `tool.result` | результат, отказ пользователя или «нет активной сессии» |
| тел → сервер | `event` | уведомления «в Hermes», «запомни» из очереди |
| тел ↔ сервер | `history.page` | страница журнала канала для ленты |
| тел ↔ сервер | `session.state` | оверлей открыт/закрыт — для гейтинга инструментов |

```json
{"type":"tool.call","id":"c-812","tool":"phone.calendar_add",
 "args":{"title":"Встреча с банком","start":"2026-09-28T10:00+03:00","duration_min":30}}
```

**Без сети:** реплики для Hermes и события копятся в очереди с отметкой времени и уходят при подключении. `tool.call`, не выполненный за 60 секунд, считается отменённым, чтобы устаревшее действие не сработало потом.

## 12. Безопасность (сервер на белом IP)

- **TLS обязателен:** Caddy + Let's Encrypt, нужен домен. WebSocket плагина — за прокси, на отдельном пути. Tailscale — поддерживаемая альтернатива.
- **Привязка устройства:** одноразовый код (как DM pairing в Hermes), после чего телефон регистрирует свой ключ из Android Keystore. Вход — подпись вызова сервера этим ключом; украденный токен без ключа бесполезен.
- **Защита от перебора:** ограничение попыток входа и частоты сообщений, бан по IP.
- **Последнее слово за телефоном:** инструменты только в активной сессии, политика и подтверждения проверяются на телефоне, П2 никогда не выполняется автоматически.
- **Журнал действий** на обеих сторонах.
- **Данные ≠ команды:** содержимое уведомлений, экрана, файлов и писем передаётся модели в явной обёртке и не может само по себе вызвать действие.

## 13. Этапы

Подробно — в `Расширенный_план.md`. Логика: сначала **тонкий сквозной прототип**. Он проверяет пять рискованных узлов по одной функции на каждый. Только потом наращиваем функции.

| Фаза | Содержание | Проверка |
|---|---|---|
| **0. Подготовка** | среда сборки, тестовый телефон, сервер + домен + Caddy, макеты оверлея | макеты утверждены, приложение ставится на телефон |
| **1. Сквозной прототип** | оверлей (караоке, эквалайзер, состояния) · GigaAM на телефоне · плагин: канал и стриминг · Hermes → `phone.set_alarm` с карточкой · 3 локальные команды без сети | сценарий демо проходит на реальном телефоне |
| **2. Надёжный канал** | лента и история, привязка устройства, очередь, новая сессия по паузе, дизайн-система | неделя вместо Telegram-бота |
| **3. Локальный мозг** | нейросетевой маршрутизатор, ~15 команд, заметки → память | 90% бытовых команд без сервера |
| **4. Телефон для Hermes** | `phone.*`, подтверждения и уточнения, экран, черновики | встреча из письма в календаре |
| **5. Уведомления** | сбор, сводка, «в Hermes», правила | «что важного пришло?» |
| **6. Файлы** | доступ к папкам, корзина, «почисти загрузки» | ничего нужного не потеряно |

## 14. Риски

| Риск | Что может случиться | Что делать |
|---|---|---|
| Обновление Hermes ломает плагин | канал перестаёт работать | ночной CI против `main`, минимальная поверхность API, откат версии |
| Hermes многословен | длинная озвучка, шум в ленте | навык `android`, сворачивание служебного, озвучка только первого абзаца |
| Стриминг в канал не заработает | долгая пауза перед голосовым ответом | проверить в Ф1; иначе промежуточный «думаю…» и озвучка по готовности |
| Роль ассистента сбрасывается при обновлении | кнопка перестаёт работать | проверка при запуске, восстановление в один тап |
| GigaAM или черновое караоке тяжелы для телефона | задержка, нагрев | загрузка по активации; на слабых устройствах — распознавание на сервере |
| Локальный маршрутизатор ошибается | не то действие | порог уверенности, короткий список функций, «не моё → Hermes», подтверждение для всего, что не П0 |
| Android убивает фоновое соединение | ответ не доходит | соединение нужно в основном при открытом оверлее; для cron-сообщений — push (ntfy/UnifiedPush) |
| Сервер на белом IP взломан | доступ к каналу | инструменты только в активной сессии, политика на телефоне, П2 руками |

## 15. Открытые вопросы

**Закрыто по исходникам Hermes:**
- стриминг — есть, через `edit_message` с накопленным текстом, по умолчанию выключен;
- гейтинг инструментов — `check_fn` не подходит, проверяем в хендлере;
- подтверждения — `_send_exec_approval_prompt` → `resolve_gateway_approval`;
- «на хранение» без ответа — `pre_gateway_dispatch` + запись в память;
- новая сессия — синтетический `/new`.

**Осталось (Ф0–Ф1):**
1. Что делает приложение Claude по долгому нажатию питания: сразу голосовой режим или обычный экран? Нужны скриншоты для макетов.
2. Скорость и нагрев GigaAM и чернового караоке на целевом телефоне.
3. Стабильность Compose внутри `VoiceInteractionSession`, работа на экране блокировки.
4. Держится ли роль ассистента на прошивке целевого телефона.
5. Есть ли aiohttp в зависимостях Hermes (чтобы не добавлять своих).
6. Совместимость onnxruntime классификатора с тем, что внутри sherpa-onnx (Ф3).
7. Как мозг получает инструменты телефона (Ф4): см. `Открытые_вопросы.md`, В3.

## 17. Гипотезы на будущее (не план)

Полный список с причинами и условиями возврата — `Будущее_развитие.md`.

Это не входит в цель проекта и не стоит в фазах. Записано, чтобы идеи не потерялись. Где есть зрелые приложения, с ними не конкурируем.

- **Долгие фоновые задачи на телефоне.** Оверлей — окно, а не процесс: его закрывает любое нажатие мимо, Home или блокировка. Долгая работа потребовала бы foreground-сервиса, прогресса в уведомлениях и возврата результата мозгу вне разговора. Пример: «рассортируй фото за лето» (4 000 фото, разметка локальной моделью, план, раскладка). Для этого есть галереи и файловые менеджеры.
- **Телефон как сопроцессор мозга.** Крупные операции над данными телефона (сканирование, дубликаты, разметка) со сводкой для мозга. Имеет смысл только вместе с предыдущим пунктом.
- **Полноценный локальный агент.** Малая LLM на телефоне (Gemma через LiteRT-LM) для многошаговых задач офлайн. Референс схемы вызова инструментов — `LiteRtLmOpenAiProxy.kt` в adybag14.
- **Модель «речь в речь» как голос спереди** (OpenAI Realtime, Gemini Live), которая передаёт сложное мозгу. Звук уходит в облако, дорого, русский не проверен.
- **Длинная диктовка на серверной GigaAM** (`register_transcription_provider` в Hermes).
