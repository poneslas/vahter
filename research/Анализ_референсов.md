## 1. Hermes: что даёт ядро (HEAD 83597d9b71)

**Platform-плагин**
- `~/.hermes/plugins/android/` + `plugin.yaml` (`kind: platform`, `requires_hermes`, `api_version`).
- Включается явно: `hermes plugins enable android`.
- Регистрация через `ctx.register_platform(...)` (`hermes_cli/plugins.py:807`).
- Обязательные методы `BasePlatformAdapter`: `connect`, `disconnect`, `send`, `get_chat_info`.
- Пример: `plugins/platforms/irc/`.

**Стабильность API**
- Методы `PluginContext` меняются только аддитивно, депрекейт живёт не меньше двух минорных релизов (`plugins/AGENTS.md:87`).
- Риск: декомпозиция PR #102117 перенесла ~1100 внутренних имён. После 2026-09-14 плагины со старыми импортами **отключаются**.
- Импортировать только документированное: `gateway.platforms.base`, `gateway.platforms.event`, `gateway.config`, `gateway.platforms._shared`.
- В CI гонять `hermes plugins compat`.
- `hermes update` не трогает `~/.hermes/plugins`, но может **отключить** плагин при конфликте зависимостей. Держать зависимостей минимум.

**Стриминг**
- По умолчанию выключен (`streaming.enabled: false`).
- Работает через `send` + `edit_message` с **накопленным** текстом (интервал 0.8 с).
- Альтернатива — нативный стрим: `SUPPORTS_NATIVE_STREAMING` + `send_stream_frame`, пример WeCom.

**Прогресс инструментов**
- Финальный ответ помечен `metadata.notify=True`, статусы и подтверждения — `_interim_send=True`. Прогресс явного флага не имеет.
- Можно переопределить `format_tool_event`.
- Настройки: `display.platforms.android.tool_progress: off|new|all`.

**Подтверждения**
- `_send_exec_approval_prompt` → кнопки «once / session / always / deny» → `resolve_gateway_approval`.
- Отдельно есть `send_clarify` и `send_slash_confirm`.

**Инструменты плагина**
- Регистрация: `ctx.register_tool(..., check_fn)`.
- `check_fn` кэшируется ~30 с на профиль, а не на сессию.
- Хендлер знает вызывающего через `get_session_env("HERMES_SESSION_PLATFORM" / "CHAT_ID")`.
- **Инструменты плагина видны на всех платформах**, поэтому в хендлере нужна проверка платформы и активной сессии.

**Сессии**
- Ключ: `agent:main:android:dm:<chat_id>`.
- **Авто-сброса по простою нет.** Таймер в адаптере отправляет синтетический `/new`.
- `/new` по умолчанию требует подтверждения: `approvals.destructive_slash_confirm`.

**Память без ответа агента**
- Хук `pre_gateway_dispatch` → `{"action":"skip"}` + `MemoryStore.add(...)`.
- Запись попадёт в промпт только в следующей сессии.
- `inject_gateway_message` запускает ход, для этой задачи не подходит.

**Голос**
- `MessageType.VOICE` + аудио транскрибируется ядром.
- GigaAM подключается как `ctx.register_transcription_provider` → `stt.provider: gigaam`.
- TTS: `play_tts` / `send_voice`, есть потоковый PCM-контракт.

**Прочее**
- Pairing: код из 8 символов, TTL 1 ч, `hermes pairing approve android <code>`, плюс `allowed_users_env`.
- Cron: `cron_deliver_env_var`. Тикер работает внутри гейтвея, поэтому живой адаптер доступен.

**Альтернативный транспорт.** Оба Kotlin/Flutter-клиента ходят в WebSocket дашборда `/api/ws` (JSON-RPC tui_gateway). Там из коробки есть стриминг, события инструментов, подтверждения и сессии. Минусы:
- это админский API дашборда (конфиг, терминал), выставлять его на белый IP опасно;
- это не канал мессенджера: нет доставки cron, нет pairing.

## 2. hermes-android (rusty4444, Flutter)

- **Лицензии нет:** `NOTICE.md` прямо говорит, что права не передаются. Сам клон — derivative с Remote Gateway.
- ~59 тыс. строк Dart, монолиты: `chat_screen.dart` на 3968 строк, `setState` повсюду. ~1000 тестов, fake gateway.
- Транспорт: `/api/ws` JSON-RPC + ws-ticket, legacy 8642 SSE. Очень проработаны журнал ходов и восстановление (`gateway_turn_journal.dart`, `gateway_turn_recovery.dart`).
- Нет роли ассистента, оверлея, инструментов телефона. Голос — только диктовка.
- **Что брать:** идеи — журнал ходов с идемпотентными id, ws-ticket, контрактные тесты против fake gateway. Код не брать.

## 3. Hermes-Mobil (Jilazem, Kotlin/Compose, MIT)

- ~16 тыс. строк, 9 коммитов, один автор. Строки UI и правила на турецком, закреплённая версия Hermes 0.19.1.
- Транспорт: `data/GatewayWsClient.kt` (`/api/ws`, backoff 0.3–30 с, reattach) и `data/HermesClient.kt` (REST дашборда).
- Роль ассистента только через ASSIST intent-filter на Activity (не VIS), `ui/LiveVoiceSheet.kt`. Есть QS-тайл `data/VoiceTileService.kt`.
- Телефон:
  - `data/PhoneIntent.kt` — regex-правила;
  - `data/PhoneTools.kt`;
  - `data/HermesNotificationListener.kt`;
  - `data/PhoneBridgeService.kt` — клиентская половина моста. **Серверного `phone_bridge.py` в репозитории нет.**
- **Что брать (MIT, с атрибуцией):**
  - `GatewayWsClient.kt`;
  - outbox и reattach из `ChatViewModel.kt`;
  - `SessionCache.kt`, `ServerProfile.kt`, `DiagLog.kt`;
  - `HermesNotificationListener.kt`, `PhoneTools.kt`;
  - `VoiceTileService.kt`, `Markdown.kt`, `MessageViews.kt`.

## 4. hermes-android (raulvidis → MianoCopilot, MIT)

- Приложение `hermes-android-bridge/app`: Kotlin, ~5.5 тыс. строк, XML UI, Ktor + OkHttp.
- Плагин `hermes-android-plugin/`:
  - **tools-плагин**, а не platform-плагин;
  - 42 инструмента, `register_skill("android")`;
  - `check_fn` пингует relay, поэтому инструменты видны, только пока телефон подключён.
- Протокол: tool → HTTP → relay `localhost:8766` (aiohttp внутри процесса Hermes) → WS → телефон. Телефон подключается исходящим соединением. Кадры `{request_id, method, path, params, body}`, бинарные стримы чанками с sha256.
- **Слабые места:**
  - pairing-код из 6 символов — единственный секрет, дающий полный контроль;
  - по умолчанию `ws://`;
  - телефон слушает на 0.0.0.0:8765;
  - токен передаётся в URL (коммит MianoCopilot);
  - accessibility с typeAllMask;
  - установка через `curl | bash`.
- **Что брать:**
  - шаблон плагина (`__init__.py`: `register_tool` + `check_fn` + skill);
  - JSON-схемы инструментов и `skill.md`;
  - корреляция `request_id` и стриминг бинарных данных;
  - `executor/ScreenReader.kt`, `ActionExecutor.kt`;
  - `service/BridgeNotificationListener.kt`, `notification/NotificationStore.kt`;
  - `client/ReconnectPolicy.kt`, `power/WakeLockManager.kt`, `audio/*`, `server/AuthRateLimiter.kt`.
- База — upstream raulvidis. Два коммита MianoCopilot не брать.

## 5. Hermes Agent Fork (adybag14, MIT)

- Hermes целиком на телефоне через Chaquopy. `android/app`: ~166 тыс. строк Kotlin, 678 коммитов автора.
- Признаки AI-churn:
  - `device/HermesDeviceDiagnosticsBridge.kt` на 29 464 строки;
  - 131 файл `RELEASE_*.md`;
  - 642 МБ mp4 в `android/release-evidence/`.
- Злого умысла и телеметрии не найдено. Но есть:
  - собственные Cloudflare-воркеры автора (каталог моделей подписан ECDSA, жалобы на контент);
  - llama-server из стороннего форка, который запускается как процесс;
  - Termux/proot, Shizuku, огромная поверхность атаки.
- Нет VIS и нет GigaAM; STT — `RecognizerIntent`.
- **Что брать:**
  - схему маппинга OpenAI tools → LiteRT-LM `ToolProvider` из `backend/LiteRtLmOpenAiProxy.kt` (LiteRT-LM 0.17.1, manual tool calling, SSE, выбор GPU/CPU);
  - идею загрузки моделей с HF с sha256-пинами (`models/`).
- Остальное — только как справочник. APK на личный телефон не ставить.

## Рекомендация

1. **Клиент:** новое приложение на Kotlin/Compose. Модули-доноры: Hermes-Mobil и raulvidis-bridge (MIT, с атрибуцией). Идеи надёжности — из rusty4444. Схема локального агента — из adybag14. Своими руками:
   - `VoiceInteractionService` и оверлей;
   - GigaAM через sherpa-onnx;
   - дизайн в стиле Claude;
   - работа с файлами через SAF.
2. **Сервер:** один плагин `android` для Hermes. Это `kind: platform` (канал, стриминг, подтверждения, cron, pairing), плюс инструменты телефона по шаблону raulvidis с проверкой «платформа android + активная сессия», плюс опционально провайдер распознавания GigaAM.
3. **Транспорт:** свой WSS-протокол плагина. `/api/ws` дашборда на белый IP не выставлять.

## 6. Гига Писарь (moznoazachem, MIT)

Пути: `upstream/giga-pisar` (macOS, Swift, 108 коммитов), `upstream/giga-pisar-win` (Windows, C#), `upstream/giga-pisar-cli` (Linux). Полный перенос опыта — в `Голосовой_контур.md`.

- **Модель:** GigaAM v3 `e2e_rnnt` int8 (пунктуация и регистр) на onnxruntime CPU, своё извлечение признаков и жадный RNN-T. 6 с речи распознаются за 0,08 с.
- **Показ текста по мере диктовки нет ни в одной версии и ни в истории коммитов** (проверено поиском по всей истории и удалённым файлам). Текст появляется целиком после отпускания клавиши. Пре-ролла и VAD тоже нет.
- **Что берём:**
  - эквалайзер: пиковый RMS 10 мс, шкала дБ с гаммой 0,6, 13 столбиков, рандом раз на всплеск, адаптивный пол шума из Windows-версии;
  - захват в родном формате со своим ресемплингом;
  - отбраковка: короче 0,4 с, «микрофон отдал тишину»;
  - нарезка длинной речи по паузам: до 25 с одним куском;
  - движение плашки;
  - принципы LLM-правки.
