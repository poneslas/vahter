# Расширенный план реализации

28.09.2026 · дополняет `ТЗ_голосовой_ассистент_Android_Hermes.md` и `План.md`. Размеры задач: **S** — до пары дней, **M** — до недели, **L** — больше недели. Это относительные оценки, не сроки.

## 1. Принципы этапности

1. **Риск раньше функций.** Первый рабочий результат — сквозной прототип: одна фраза проходит весь путь от кнопки до действия. Каждый рискованный узел покрыт одной функцией.
2. **Каждая фаза заканчивается проверкой в жизни.** Пишем сценарий демо, который проходится на реальном телефоне, а не только тесты.
3. **Сначала замеры, потом решения.** Скорость оверлея, распознавания и нагрев меряем в Ф1. По результатам решаем, какие запасные варианты включать.
4. **Hermes не трогаем.** Всё серверное живёт в плагине `android`. Опираемся только на документированный API платформ-плагинов.
5. **Дизайн оверлея финальный с первого прототипа.** Это главный экран продукта и один из рисков. Остальные экраны в прототипе служебные.

```jsonc

{"type":"auth","device":"pixel-8","token":"…"}
{"type":"hello","app":"0.1.0","state":{"battery":81,"net":"wifi"},
 "capabilities":[{"name":"phone.set_alarm","version":1,"cost":"instant","privacy":"none",
                   "confirm":"П1","schema":{"time":"HH:MM","label":"string?"}}]}

{"type":"tool.result","id":"c-3","ok":true,"result":{"alarm":"06:52"}}

// сервер → телефон
{"type":"reply.start","id":"r-9","re":"m-17"}
{"type":"reply.update","id":"r-9","text":"Завтра в Москве +12, облачно"}   // накопленный текст
{"type":"reply.final","id":"r-9","text":"Завтра в Москве +12, облачно, днём дождь."}
```

Схемы лежат в `protocol/` и используются в тестах обеих сторон.

### 5.7. Сценарий демо фазы 1

1. На экране открыто любое приложение. Долгое нажатие питания: оверлей, эквалайзер реагирует на голос.
2. Режим полёта. «Таймер на пять минут»: таймер стоит, карточка с «Отменить».
3. Сеть есть. «Какая погода завтра?»: слова бегут во время речи, ответ приходит потоком текстом.
4. «Поставь будильник на время восхода солнца завтра»: карточка «Будильник 06:52 — Поставить?», «Да», будильник в «Часах».
5. То же с заблокированного экрана: вопрос работает, действие просит разблокировку.
6. В Hermes (CLI или дашборд) видна сессия канала `android` со всеми репликами.

### 5.8. Решения по итогам фазы 1

| Если | То |
|---|---|
| Compose в сессии медленный или нестабильный | оверлей на View, Compose остаётся в ленте и настройках |
| GigaAM дольше 0,5 с или греет телефон | GigaAM грузится только по кнопке, на слабых телефонах распознавание уходит на сервер (плагин + серверная GigaAM) |
| Черновое караоке сажает батарею | реже обновлять или потоковая модель sherpa-onnx только для черновика |
| Роль ассистента не держится на прошивке | основным входом становятся плитка и виджет |
| Стриминг из Hermes не идёт в плагин | ответ целиком с индикатором «думаю», озвучка по готовности |

## 11. После фаз: озвучка и гипотезы

- **Озвучка ответа** — опция, когда основное работает: системный TTS с караоке ответа, затем сравнение 3–4 голосов на 20 реальных ответах (`UX_оверлея.md`, раздел 7).
- Долгие фоновые задачи, сопроцессор, локальный агент, модель «речь в речь», серверная диктовка — **гипотезы, не план** (ТЗ, раздел 17).

## 12. Сквозные темы

| Тема | Что делаем |
|---|---|
| Безопасность | TLS только через Caddy, токен не в URL, ключ устройства, ограничение попыток, журнал действий на обеих сторонах |
| Тесты | плагин: pytest + фейковый телефон; приложение: unit-тесты маршрутизатора и парсеров, инструментальные тесты оверлея |
| Замеры | скрипт замеров задержек и нагрева, результаты в `docs/замеры.md` после каждой фазы |
| Обновления Hermes | ночной CI против `main` и последнего релиза, `UPSTREAM_TESTED.md`, откат на проверенную версию |
