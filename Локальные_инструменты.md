# Локальные инструменты: реестр, исполнение, отображение

17.10.2026 · уточняет ТЗ, разделы 5, 8 и 10.5. Как вызовы выглядят на экране, описано в `UX_оверлея.md`, макеты лежат в `design/Макеты_оверлея.html`.

**Граница.** Все инструменты короткие: секунды, пока открыт разговор. Долгих фоновых задач нет (ТЗ, разделы 2 и 17).

## 1. Один реестр, три вызывающих

Любое действие на телефоне — это **инструмент** из одного реестра. Вызвать его могут трое:

| Кто вызывает | Когда появляется | Как попадает в реестр |
|---|---|---|
| **Правила** | Ф1 | шаблон фразы → имя инструмента + параметры |
| **Локальный маршрутизатор** | Ф3 | классификатор → имя инструмента, парсеры → параметры |
| **Hermes** | Ф1 (`set_alarm`), Ф4 — весь набор | кадр `tool.call` с именем `phone.<инструмент>` |

У всех трёх путь дальше одинаковый: **проверка политики → уточнение → подтверждение → исполнение → результат → возможность отменить → запись в журнал.** Отличаются только две вещи: подпись «кто это сделал» на карточке и уровень подтверждения, потому что для Hermes он бывает строже.

Так у пользователя одна модель в голове: «действие на телефоне выглядит одинаково, кто бы его ни запросил». А у нас один исполнитель и один набор тестов.

## 2. Описание инструмента

Описание инструмента — это запись манифеста возможностей (ТЗ 10.5). Из неё же собирается карточка в интерфейсе, кадр `hello` для Hermes и датасет для маршрутизатора.

```jsonc
{
  "name": "alarm.set",                  // для Hermes: phone.alarm.set
  "version": 1,
  "title": "Будильник",                 // заголовок карточки
  "icon": "alarm",
  "describe": "Поставить будильник на время. Не для таймеров: «через N минут» — это timer.set.",
  "params": {                           // JSON Schema
    "time":  {"type": "string", "format": "HH:MM"},
    "days":  {"type": "array", "items": "mon..sun", "optional": true},
    "label": {"type": "string", "optional": true}
  },
  "result": {"alarm_time": "HH:MM", "in": "duration"},
  "summary": "{time}{, label}",          // строка для карточки и журнала
  "placement": "local+hermes",           // local | local+hermes | hermes
  "confirm": {"local": "П0", "hermes": "П1"},
  "undo": "inverse",                     // none | inverse | trash | snapshot
  "cost": "instant",                     // instant | seconds; долгих задач нет
  "privacy": "none",                     // none | metadata | content_on_yes
  "requires": {"unlock": false, "network": false, "permission": null, "model": null},
  "lockscreen": "ask_unlock",            // allow | ask_unlock | deny
  "examples": ["поставь будильник на семь сорок", "разбуди меня в 6:30 по будням"]
}
```

Правила для описаний:
- `describe` пишем для модели: что делает инструмент и **чем он не является**. Это главный способ уберечь Hermes и маршрутизатор от путаницы между похожими инструментами.
- `summary` — одна строка без глаголов в прошедшем времени. Глагол подставляет интерфейс по состоянию: «Поставлю», «Поставлено», «Отменено».
- `examples` — 3–10 фраз. В Ф3 из них и синтетики собирается датасет классификатора.

## 3. Жизненный цикл вызова

```
 получен ─► политика ─┬─► отказ (выключен / нет прав / заблокирован экран)
                      │
                      ▼
               параметры полны? ──нет──► уточнение «На когда?» ──► (ответ) ──┐
                      │да                                                   │
                      ◄─────────────────────────────────────────────────────┘
                      ▼
              нужно подтверждение? ──П1──► карточка «Да / Изменить / Отмена»
                      │П0                     │да        │изменить   │отмена / 60 с
                      ▼                       ▼          ▼           ▼
                  исполнение ◄────────────────┘    правка полей   отменён
                      │
              ┌───────┴────────┐
              ▼                ▼
          выполнено         ошибка ──► понятная причина + «Повторить» / «Открыть Часы»
              │
              ▼
     окно отмены (кнопка «Отменить» на карточке, без срока для обратимых)
              │
              ▼
           журнал
```

| Состояние | Что видит пользователь | Таймаут |
|---|---|---|
| Уточнение | вопрос голосом и текстом в оверлее, поле подсвечено на черновой карточке | 15 с тишины → карточка остаётся в ленте, «Ответить» |
| Ждёт подтверждения | карточка с параметрами, кнопки, голосом «да» / «нет» | 60 с для вызова от Hermes, после этого `tool.result: expired`; локальное — без срока, пока открыт оверлей |
| Выполняется | на карточке прогресс | у `instant` — 3 с, у `seconds` — 15 с, потом ошибка |
| Выполнено | галочка, итог в одну строку, «Отменить» | — |
| Отменено | карточка становится серой, строка «Отменено» | — |

**П2 (черновики сообщений)** не исполняется никогда: исполнитель открывает приложение с готовым текстом, отправляет человек. На карточке кнопка «Открыть в Telegram», а не «Да».

## 4. Политика

Политика живёт на телефоне. Hermes её не видит в деталях и понизить не может.

| Настройка | Значения | По умолчанию |
|---|---|---|
| Инструмент включён | да / нет | по реестру |
| Подтверждение для Hermes | П1 / П2; П0 только для чтения | по реестру |
| Подтверждение для локальных | П0 / П1 | по реестру |
| На экране блокировки | разрешить / просить разблокировку / запретить | `ask_unlock` для действий с данными |
| Hermes может вызывать | да / нет | да для `local+hermes` |

Проверка политики идёт **до** показа карточки. Hermes получает понятный отказ (`denied: disabled_by_user`), а не таймаут, и не переспрашивает.

## 5. Реестр по фазам

Подтверждения указаны в формате «локально / от Hermes».

### Ф1: проверка пути

| Инструмент | Параметры | Подтв. | Отмена | Как сделано |
|---|---|---|---|---|
| `timer.set` | `duration`, `label?` | П0 / П1 | `inverse` через «Часы» | `AlarmClock.ACTION_SET_TIMER`, `EXTRA_SKIP_UI` |
| `alarm.set` | `time`, `days?`, `label?` | П0 / П1 | `inverse` | `AlarmClock.ACTION_SET_ALARM`, `EXTRA_SKIP_UI` |
| `torch.set` | `on` | П0 / — | `inverse` | `CameraManager.setTorchMode` |

### Ф3–Ф4: бытовой набор

| Инструмент | Параметры | Подтв. | Отмена | Как сделано |
|---|---|---|---|---|
| `alarm.list`, `alarm.dismiss` | — / `alarm_id` | П0 / П1 | — | `ACTION_SHOW_ALARMS`, `ACTION_DISMISS_ALARM` (открывает «Часы»: API не даёт отменить молча) |
| `calendar.add` | `title`, `start`, `duration`, `place?` | П0 / П1 | `inverse` (удалить созданное) | `CalendarContract`, разрешение календаря |
| `calendar.query` | `from`, `to` | П0 / П0 | — | `CalendarContract` |
| `note.remember` | `text` | П0 / — | `inverse` | уходит в Hermes как событие «в память»; без сети — очередь |
| `location.get` | — | П0 / П1 | — | FusedLocation |
| `place.save` | `name` («машина») | П0 / — | `inverse` | координаты + фото по желанию, локально + в Hermes |
| `call.dial` | `contact` или `number` | П1 / — | — | `ACTION_DIAL`; `ACTION_CALL` только по настройке |
| `message.draft` | `app`, `contact`, `text` | П2 / П2 | — | открыть приложение с текстом (`ACTION_SEND`, `smsto:`) |
| `media.control` | `play/pause/next/prev` | П0 / П1 | — | `MediaSessionManager` (нужен доступ к уведомлениям) |
| `volume.set` | `stream`, `level` | П0 / П1 | `snapshot` | `AudioManager` |
| `dnd.set` | `on`, `until?` | П0 / П1 | `snapshot` | `NotificationManager`, доступ к «Не беспокоить» |
| `settings.open` | `wifi`, `bluetooth`, `internet`, `nfc`… | П0 / — | — | `Settings.Panel`: с Android 10 приложения не могут сами включать Wi-Fi и Bluetooth |
| `app.open` | `app` | П0 / П1 | — | `PackageManager` + launch intent |
| `screen.read` | — | П1 / П1 | — | `AssistStructure` и скриншот из `VoiceInteractionSession`, только когда оверлей открыт |

### Ф5–Ф6: уведомления и файлы

| Инструмент | Параметры | Подтв. | Отмена | Как сделано |
|---|---|---|---|---|
| `notifications.recent` | `app?`, `since?` | П0 / П1 | — | локальная база `NotificationListenerService` |
| `notifications.forward` | `ids` | П1 / — | — | событие в Hermes в обёртке «данные, не команда» |
| `files.scan` | `folder`, фильтры | П0 / П0 | — | SAF, сводка за секунды; большие папки — первые N файлов и честное «показаны не все» |
| `files.search` | `name?`, `type?`, `size?`, `date?` | П0 / П0 | — | SAF |
| `files.plan` | `ops[]` | показывается всегда | — | строит план и отдаёт `plan_id` |
| `files.apply` | `plan_id` | П1 / П1 | `trash` + журнал | только план, показанный пользователю |
| `files.restore` | `op_id` | П0 / П1 | — | возврат из `.trash` |

У Hermes нет произвольных `files.move` и `files.trash`. Любое изменение файлов идёт через `plan` → карточка → `apply`. Так одна карточка показывает всё, что произойдёт, и отменяется одним журналом.

## 6. Если параметра не хватает

- **Локально:** маршрутизатор знает обязательные поля из схемы. Не хватает — вопрос голосом («На когда?»). Ответ в следующей фразе дополняет тот же вызов. Ответ не по теме уходит обычным путём, а неполный вызов остаётся черновиком в ленте.
- **От Hermes:** Hermes сам спрашивает пользователя. Если вызов пришёл с ошибкой в параметрах, телефон отвечает `invalid_params` с описанием поля, и Hermes исправляет вызов. Телефон за Hermes не переспрашивает.
- **Двусмысленность** («позвони Саше», а Саш трое) — карточка выбора, П1. Выбор запоминается как прозвище: локально и в памяти Hermes.

## 7. Что уходит в Hermes

| Вызов пришёл от | Что Hermes узнаёт |
|---|---|
| Hermes | `tool.result`: итог в схеме `result`, отказ пользователя или причина ошибки |
| правило или маршрутизатор | ничего сразу. При следующей реплике в Hermes телефон прикладывает к ней короткую сводку «на телефоне: поставлен будильник 07:40» в контексте `ctx.recent_actions`, чтобы «а перенеси его на 8» работало |
| офлайн | `note.remember` и `notifications.forward` ждут в очереди с исходным временем |

Результаты компактные: числа, имена, идентификаторы. Содержимое файлов, уведомлений и экрана Hermes получает только в обёртке «данные, не инструкция» и только по `privacy` инструмента.

## 8. Журнал действий

Одна таблица в Room, по ней строятся экран «Журнал» и строки действий в ленте.

| Поле | Пример |
|---|---|
| `at` | 2026-10-17 07:12:04 |
| `tool`, `version` | `alarm.set`, 1 |
| `caller` | `rule` / `router` / `hermes` |
| `phrase` | «разбуди меня в семь сорок» (для локальных) |
| `session_id`, `call_id` | для вызовов Hermes |
| `params`, `result` | JSON |
| `confirm` | `П0` / `yes_tap` / `yes_voice` / `denied` / `expired` |
| `undo` | данные для отмены и статус: `available` / `done` / `expired` |
| `lockscreen` | был ли экран заблокирован |

Хранение — 90 дней. Записи о файлах хранятся, пока файл лежит в корзине.

## 9. Реализация в приложении

```
local/
  registry/     описания инструментов (Kotlin DSL → JSON манифеста)
  policy/       настройки пользователя, проверка до карточки
  executors/    по одному классу на инструмент: execute(params) → Result, undo(token)
  router/       Ф1 правила; Ф3 классификатор + парсеры времени, чисел, контактов
  journal/      Room-таблица, запись и отмена
```

- Исполнитель не знает, кто его вызвал. Об этом знают только политика и интерфейс.
- У каждого исполнителя есть фейковая реализация для эмулятора и тестов: проверка пути без реальных «Часов» и календаря.
- Тест-векторы лежат в `protocol/`: фраза → ожидаемый вызов для правил и маршрутизатора; `tool.call` → ожидаемая карточка и `tool.result` для Hermes.

## 10. Открытые вопросы

1. Можно ли на целевом телефоне ставить таймер и будильник с `EXTRA_SKIP_UI` без открытия «Часов»: это зависит от приложения часов производителя.
2. Нужен ли свой таймер внутри приложения (foreground-сервис), если «Часы» производителя открываются на каждый вызов.
3. Сколько инструментов отдавать Hermes сразу: весь реестр в `hello` или только те, что нужны в текущем навыке. Длинный список инструментов ухудшает выбор у модели. Меряем в Ф4.
