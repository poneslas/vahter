## 4. Средний горизонт: доработки мозга и каналов

### Архив артефактов (В20)

**Проблема.** У Hermes нет реестра файлов. Входящие и исходящие файлы лежат в `~/.hermes/cache/…` и удаляются через 24 часа (`gateway/run.py`, `_housekeeping_media_caches`). Долгосрочный архив сейчас — только облако Telegram.

**Предложение** — отдельный плагин Hermes, не связанный с приложением:
- **входящие:** хук `pre_gateway_dispatch` копирует файлы из любого канала до очистки кэша;
- **исходящие:** пути из текста ответа (`post_llm_call`), файлы от инструментов (`post_tool_call`);
- **индекс** в SQLite: канал, сессия, направление, имя, тип, размер, время, соседний текст, хеш;
- **инструмент** `artifacts.search` / `artifacts.send`: «найди тот PDF с договором» в любом канале;
- **экран «Файлы»** в приложении.

Решить: срок хранения и квоту, шифрование, что не архивировать (голосовые, файлы из чужих групп).

### Telegram-представитель (В5)

- Отдельный профиль Hermes со своим ботом, памятью и ролью в `SOUL.md`.
- В группах: privacy mode выключен или бот — админ; `require_mention: true`, `observe_unmentioned_group_messages: true`, список разрешённых чатов. Читает всё, отвечает только на упоминание.
- Регулярная сводка — cron в этом профиле, доставка тебе.
- Безопасность: чужие сообщения — недоверенный ввод. Минимум инструментов, нет доступа к основной памяти и телефону, связь с основным мозгом — только сводками в одну сторону.
- Ограничения Telegram: это бот, а не ты; добавить его может только админ; сообщений других ботов и истории до своего прихода он не видит. Userbot не делаем: нарушает правила Telegram.

Источник: `reference/hermes-agent/website/docs/user-guide/messaging/telegram.md`, `profiles.md`.

## 5. Гипотезы: даже не план

| Гипотеза | Почему нет |
|---|---|
| Долгие фоновые задачи на телефоне («рассортируй фото за лето») | лист — окно, а не процесс; нужен foreground-сервис, прогресс, ограничения Android 14+. Для этого есть галереи и файловые менеджеры |
| Телефон как сопроцессор мозга (сканирование, разметка, дубликаты) | имеет смысл только вместе с долгими задачами |
| Локальный агент на малой LLM (LiteRT-LM) | отдельный продукт; референс — `LiteRtLmOpenAiProxy.kt` в adybag14 |
| Модель «речь в речь» (OpenAI Realtime, Gemini Live) как голос спереди | звук в облаке, дорого, русский не подтверждён, два мозга с раздельной памятью |
| Длинная диктовка на серверной GigaAM | основа есть: `giga-pisar-cli`, OpenAI-совместимый `/v1/audio/transcriptions` |
| Wake word | батарея и ложные срабатывания; если понадобится — KWS из sherpa-onnx |
| Фоновый голосовой режим с выключенным экраном | foreground-сервис с микрофоном; для коротких задач не нужен |
| Управление чужими приложениями через спецвозможности | ломается с обновлениями, полный контроль над телефоном |

## 6. Hermes как второй мозг: риски и метрики (к В1)

**Почему он нужен вторым.** MIT, любые модели, мессенджеры и cron из коробки, нативно говорит ACP и MCP.

**Почему рискован** (данные на 17.10.2026, подробно — `research/Мозг_и_стандарты.md`):
- 19 тыс. коммитов за месяц;
- в сентябре сдвинулись около 2 100 внутренних имён, плагины со старыми импортами отключаются;
- 33,7 тыс. открытых PR;
- один ключевой мейнтейнер (~40 % коммитов);
- открытые баги по нашей теме (доставка heartbeat, сжатие в gateway).

**Меряем на этапах 1–2**, гоняя те же сценарии через Claude Code:

| Метрика | Переключаемся, если |
|---|---|
| Поломки плагина от обновлений Hermes | чаще раза в месяц |
| Доставка сообщений вне хода | ниже 99 % |
| Задержка голосового хода, p50 / p95 | заметно хуже Claude Code |
| Токены и деньги за ход (одна модель) | дороже на 20 % и больше |
| Успешность многошаговых задач (одна модель) | хуже на 20 % и больше |

**Уже сейчас, независимо от выбора:**
- Hermes закреплён на стабильной версии, обновления — вручную после проверки совместимости;
- плагин импортирует только документированный API;
- инструменты описаны MCP-схемами.

## 7. Баги с телефона (S24, сборка 0.2.1)

Копим и чиним пачкой, чтобы не переустанавливать ради каждого. **1–9 исправлены в 0.3.0, 10–14 — в 0.3.1, 15–18 — в 0.4.0** (проверено на эмуляторе; на S24 — проверить: выключение будильника в «Часах» Samsung, «Не беспокоить», громкость звонка).

1. **Статус «Цифровой помощник» не обновляется после возврата из системных настроек** (19.10). Помощник выбран, а в приложении по-прежнему «не выбран».
   Причина (по коду): «Настройки» читают `isRoleHeld` один раз при отрисовке и при возврате в приложение не перечитывают. На первом запуске перечитывание держится на чтении `tick` пустым выражением — ненадёжно. Тем же страдают «Боковая кнопка», «Микрофон», «Уведомления».
   Исправление: счётчик «вернулись в приложение» в `onResume` у `MainActivity`; все статусы системных настроек читаются от него.
2. **Строка действия не говорит, что сделано** (19.10). «Будильник · 7:00 / на телефоне» — непонятно, поставлен ли. Нужен глагол и срок: «Будильник поставлен · 7:00», «на телефоне · прозвенит через 9 ч 12 мин»; таймер — «Таймер запущен · 5:00» и обратный отсчёт; неудача — красным «Не получилось». Строки вообще слишком скупые — обсуждаем вид (ниже, «Строки действий»).
3. **«Отключи будильник» не понимается** (19.10). Функции нет. Android даёт `AlarmClock.ACTION_DISMISS_ALARM` с поиском по времени или подписи: выключает ближайшее срабатывание; удалить будильник из «Часов» публичным API нельзя. Поддержку в Samsung «Часах» проверить на S24. Таймеры: `ACTION_DISMISS_TIMER` — только звенящий.
4. **Кнопки «Открыть Часы» / «Открыть таймеры»** (19.10): «Часы» с большой буквы, и ведут не туда, куда сказано. Нужно «Открыть будильники» и «Открыть таймеры», со строчной.
5. **Язычок сверху листа не работает** (19.10). Ожидание: потянуть вниз — лист сворачивается (закрывается), вверх — разворачивается в приложение. Сейчас — только нажатие, и то не всегда попадает.
6. **«Открыть будильники / таймеры» из листа открывает «Часы» под листом** (19.10). Известное поведение S24 (окна из листа уходят под него). Исправление — как у выбора фото: сначала спрятать лист, потом открыть «Часы».
7. **«Какая сегодня погода?» — «у меня только будильник и таймер»** (19.10). DeepSeek по API не ходит в интернет: о сегодняшней погоде он знать не может, а системный промпт толкает его говорить про функции телефона. Решение (19.10): функцию погоды не делаем. Промпт — честно «у этой модели нет доступа к интернету», без перечисления функций, и предложение подключить личного агента (Hermes: поиск, погода). Погоду как функцию телефона добавим, если понадобится.
8. **«Что это?»: после отправки фото сам включается микрофон** (19.10). Причина: камера заменяет лист целиком; когда лист возвращается, строка ввода создаётся заново и повторно выполняет «вызов кнопкой — сразу слушать». Исправление — помечать вызов отработанным; в фото-режимах вызов кнопкой и так открывает камеру, а не микрофон.
9. **Камера: системный «назад» выходит на домашний экран, а не в лист** (19.10). Нужно: «назад» в камере = ✕ (заморожен кадр — переснять; иначе — вернуться в лист). Перехватить `onBackPressed` сессии помощника.
10. **Нажатие на уведомление об ответе открывает камеру, а не разговор** (19.10, 0.3.0). Было: режим «Что это?», открыт видоискатель, пришёл ответ — уведомление. По нажатию снова видоискатель.
    Причина (по коду): `OpenSheetReceiver` открывает лист без пометки источника, и лист считает это вызовом боковой кнопкой: в фото-режиме — «сразу камера», в голосовом — «сразу слушать».
    Исправление: уведомление передаёт `src=notification` — лист открывается на разговоре с ответом, без камеры и без записи.
11. **«Выключи таймер» → выключился «будильник 0:05», поверх всего открылись «Часы», а в ответе «Таймер остановлен»** (19.10, 0.3.0, S24). Три ошибки сразу:
    - нет функции для таймера, и модель взяла «выключить будильник», придумав время 0:05 из «5 минут»;
    - «выключить будильник» открывает «Часы» поверх листа (Samsung показывает список) — человек не просил ничего открывать;
    - функция вернула «готово», и модель уверенно соврала. На деле ничего не выключено.
    Что можно по-честному: Android даёт программам выключить только **звенящий** таймер (`ACTION_DISMISS_TIMER`); остановить идущий таймер извне нельзя ни в Google, ни, скорее всего, в Samsung «Часах».
    Исправление: (а) функция `timer_stop` — звенит: выключить; идёт: строка «Таймер не остановлен — Android не даёт остановить его из другого приложения» с кнопкой «Открыть таймеры», ничего не открывать самим; (б) у `alarm_dismiss` — в описании «только будильники, не таймеры», время только из слов человека; результат — «открыл список в «Часах», выключено ли — не знаю», строка без зелёной галочки; (в) правило в промпте: говорить «сделано» только если функция вернула ok и не «не знаю».
12. **Отмена и выключение для всего, что можно** (19.10). Разбор действий:
    - уже есть: фонарик «Выключить», громкость «Вернуть», «Не беспокоить» «Отменить», событие «Удалить»;
    - добавить: музыка «Пауза ↔ Играть»; заметки и места — «Удалить» и голосом («забудь про парковку»); выключение будильника — «Вернуть» (поставить заново); событие — удалить голосом («удали встречу у стоматолога», с «Да»);
    - будильник: удалить из «Часов» нельзя — только попросить выключить по времени (Google удаляет разовый, Samsung, вероятно, покажет список); строка без галочки, «выключите в списке, если остался»;
    - таймер — решение 19.10: свой таймер пока не делаем. «Выключи таймер»: звенит — `ACTION_DISMISS_TIMER`; идёт — сразу «Часы» на вкладке таймеров (`ACTION_SHOW_TIMERS`), строка «Остановите в Часах», без галочки. Проверить на S24, что «Открыть таймеры» в Samsung «Часах» попадает на вкладку таймеров;
    - только смотрят или только открывают экран (местоположение, календарь, ближайший будильник, приложения, настройки, звонок, сообщение) — отменять нечего.
13. **Настройка «Слушать сразу при вызове»** (19.10). Сейчас голосовой режим всегда сразу пишет при вызове. Нужен переключатель в «Настройки → Вызов»: «Слушать сразу при вызове» — «Боковая кнопка: запись начинается сама. Из уведомлений и приложения — нет». Включается только вызовом помощника (боковая кнопка, жест, экран блокировки); уведомление (см. №10), возврат из камеры или настроек, переключение режима — никогда. По умолчанию — включено (как сейчас). Фото-режимы — по-прежнему «сразу камера» при вызове, отдельно не настраивается.
14. **Встроенные режимы не редактируются** (19.10). «Ассистент», «Переводчик», «Что это?»: только включить или выключить и «Начать заново». Название, значок, промпт, подсказки, «Принимает», «Главное» — только смотреть. Свои режимы — как сейчас.
15. **Мультиязычность** (19.10; сделано в 0.4.0: ~610 строк в `strings.xml`, `tr()` / `trp()`, тексты встроенных режимов — из ресурсов; осталось — слова локальных команд по языкам и описания функций для мозга). Все тексты интерфейса — в ресурсы `strings.xml` (сейчас строки зашиты в код). Исходный язык — русский (`values/`), переводы — `values-xx/`, plurals — через `<plurals>`. Отдельно:
    - тексты встроенных режимов (название, подсказки, промпт) — из ресурсов по id режима, а не из сохранённого JSON, иначе язык не сменится;
    - системный промпт мозга — на языке интерфейса, ответ — на языке человека;
    - распознавание пока только русское (GigaAM) — при другом языке интерфейса честно сказать «голос — только по-русски»;
    - слова для локальных правил (таймер, будильник, фонарик) — по языкам;
    - взятый у Писаря код (`pisar/`) уже на ресурсах — проверить оставшиеся строки.
16. **Лист с клавиатурой подскакивает слишком высоко, между листом и клавиатурой пустота** (19.10, 0.3.1, S24, замечено в «Переводчике»).
    Причина (по коду, без проверки): клавиатура учитывается дважды — окно листа уже ужимается под неё (`SOFT_INPUT_ADJUST_RESIZE` в `AssistSession`), а Compose добавляет снизу ещё отступ на её высоту (`imePadding()` в `SheetScreen`); плюс отступ под полоску навигации, которой при открытой клавиатуре нет. В приложении тот же приём (`adjustResize` + `imePadding`) — проверить и там.
    Исправление: оставить один способ — окно не ужимать (`ADJUST_NOTHING`), отступ считает только Compose (`imePadding` вместе с полоской навигации, без двойного сложения). Проверить на эмуляторе с клавиатурой и на S24.
17. **«Обрезать» неудобно: рамка у самых краёв экрана, за неё не ухватиться** (19.10, 0.3.1, S24). Сейчас обрезка — «проведите пальцем от угла до угла», кадр во весь экран, захватить край нельзя.
    Как надо (как в редакторе фото Android/Samsung): по «Обрезать» кадр уменьшается и встаёт с отступами со всех сторон (~24 dp, целиком, без подрезки); сразу появляется рамка на весь кадр с кругляшками в углах (видимые ~20 dp, зона касания 48 dp) и черточками по серединам сторон; тянуть угол — менять размер, тянуть сторону — двигать её, тянуть внутри — двигать рамку; вне рамки затемнено; сетка 3×3 во время перетаскивания; «Сбросить» — снова весь кадр. Рамка не меньше ~15 % кадра. Обвести и стрелка рисуются на том же уменьшенном кадре.
18. **Камера: ✕ и название режима залезают под вырез фронтальной камеры** (19.10, 0.3.1, S24). Верх считается только по строке состояния; в окне помощника её отступ может быть нулевым, а вырез экрана (`displayCutout`) не учитывается. Исправление: элементы управления — по `WindowInsets.safeDrawing` (строка состояния + вырез + жесты), видоискатель может уходить под вырез. Вид камеры целиком — обсуждаем (ответ 19.10, «камера в листе»).
19. **Составная фраза терялась наполовину** (19.10, 0.4.3). «Поставь будильник на 7:30 и таймер на одну минуту» перехватывало локальное правило таймера, будильник пропадал. Исправлено в 0.4.4: составную фразу (связки «и», «а потом», запятая или два разных действия) берёт мозг и раскладывает на шаги; без сети — по частям локально, непонятое — честной строкой «без сети понял не всё».
20. **При переключении режима лента открывалась не с конца** (19.10, 0.4.5). Исправлено в 0.5.0: у каждого режима своё положение ленты, при переключении — сразу последнее сообщение.
21. **Элементы у правого края прижаты** (19.10). Выровнено в 0.5.0: поля ленты, строки ввода, вкладок, шапки листа и камеры — 16 dp, как у системных экранов Android.

## 9. Прототип ↔ приложение: каноны обмена
Не общий код и не полное соответствие: прототип похож на приложение на 85–90%, остальное — демо. Одно периодически вливается в другое в обе стороны.

- **Совпадают обязательно:** тексты (канон — Продукт 5.12), набор экранов и состояний, порядок действий, цвета и формы.
- **Могут отличаться:** заглушки мозга и телефона, обвязка демо («Сценарии», «Мир», «Журнал»), скорость анимаций.
- **Прототип → приложение:** каждая правка прототипа сразу пишется в 9.1. По умолчанию её переносим; если она только для показа — пометка «только демо», такие не переносим.
- **Приложение → прототип:** если на телефоне сделано иначе (ограничение Android, находка на S24), прототип подтягиваем и пишем в 9.2.
- **Вливание** — по команде, пачкой: 9.1 перенесено в приложение, 9.2 — в прототип, расхождения либо исправлены, либо записаны здесь как осознанные. Перенесённое вычёркиваем. Тексты сверяем со `strings.xml` при вливании, а не при каждом запуске; скриншот-сверок нет.
Соответствие файлов прототипа и пакетов приложения — Архитектура, раздел 14 (таблица). Страницы (`chat`, `settings`, `brain`, `actions`, `journal`, `hermes`, `voice`, `mode`) и шаги мастера (`welcome … brain`) называются одинаково; в комментариях Kotlin — имена функций и классов CSS прототипа.

### 9.2. Из приложения в прототип

- 21.10 · Hermes через API-сервер: страница Hermes (ссылка-приглашение, вставить, адрес и ключ), экран Telegram с навыком vahter, сценарии «Серия сообщений / Картинки / Подтверждение команды / Уточнение» переписаны под API (шаги tool.started, без плана, approval.request как есть, уточнение текстом, файлы из vahter-out), журнал объясняет задачу /v1/runs и steer.
- **Окно выбора закрывается системным «Назад» (21.10):** политика действия, возврат к Ассистенту и прочие списки (`Dialogs.kt`, `Choice`) — «Назад» = «Отмена». В прототипе системного «Назад» нет, переносить нечего.
- **Камера из листа после разрешения (0.7.6, Samsung):** разрешение спрашивает приложение (из листа системное окно уходит под лист); после «Разрешить» лист возвращается уже с открытой камерой (`Sheet.cameraAfterShow`), второй раз жать не нужно. Вылет при первом открытии на Samsung не воспроизвёлся на эмуляторе — нужен журнал с телефона (`adb logcat -b crash`). В прототипе разрешение камеры не спрашивается.
- **ColorOS: Вахтёра нет в «Цифровом помощнике» (0.7.4, OPPO Find X9 Pro, ColorOS 16, 20.10):** роль ASSISTANT система выдаёт (`cmd role add-role-holder` прошёл), но список ColorOS собирает по активностям с `ACTION_ASSIST` — у Claude, Алисы, Яндекса, Firefox они есть, у нас был только сервис помощника. Добавлен фильтр `ACTION_ASSIST` на прозрачную `TileOpen` (открывает лист, вызов как с кнопки). Там же: шестерёнка рядом с Вахтёром в системном списке — `settingsActivity` → псевдоним `SettingsEntry`, сразу «Настройки». На OPPO лист открылся и боковой кнопкой (после системного вопроса ColorOS), и свайпом из угла. В прототипе это не видно — только системные экраны.
