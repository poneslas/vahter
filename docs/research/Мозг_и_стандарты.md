## 1. Задача

Приложение не должно зависеть от Hermes. Если через полгода окажется, что Claude Code, Codex или следующий агент работает лучше, смена мозга должна стоить **одного адаптера**, а не переписывания приложения.

Повод: знакомые держат как личного агента сам Claude Code в консоли с подключённым Telegram, без Hermes. Компакция, длина сессии и память там работают сами.

## 2. Где ставить адаптер

| | A. Адаптеры в приложении | B. Адаптер на стороне мозга | Гибрид: контракт + шлюз |
|---|---|---|---|
| Как | приложение умеет говорить с Hermes, Claude Code и т. д. | у каждого мозга свой плагин или мост, который говорит на нашем протоколе | приложение говорит на одном протоколе; на сервере тонкий наш шлюз с драйверами мозгов |
| Смена мозга | новый APK | новый плагин или мост | новый драйвер в шлюзе, приложение не трогаем |
| Инструменты телефона | разная механика под каждый мозг | в каждом плагине заново | один MCP-сервер в шлюзе, его понимает любой мозг |
| Пуши, история, офлайн-очередь | в приложении под каждый мозг | в каждом плагине | один раз в шлюзе |
| Минусы | stdio-агентов на телефоне не запустишь; протоколы мозгов разные и быстро меняются | повторяем одно и то же на каждый мозг | свой сервис на сервере, его надо поддерживать |

**Вариант A отпадает.** Агенты вроде Claude Code и Hermes (через ACP) живут как процессы на сервере, а их протоколы меняются раз в несколько недель. Каждая смена означала бы новый APK.

## 3. Какие стандарты есть (октябрь 2026)

| Стандарт | Что покрывает | Кто говорит | Годится нам |
|---|---|---|---|
| **ACP** (Agent Client Protocol) | сессии, стриминг ответа, вызовы инструментов со статусами, запрос разрешения (`session/request_permission` — наши карточки), уточнения, подключение клиентских MCP-серверов | Hermes нативно (`hermes acp`), Claude Code через `claude-agent-acp`, Codex через адаптер, Gemini CLI, OpenClaw (урезанно), Goose и др. | **да, как форма контракта.** Минусы: официально только stdio, удалённый WebSocket-транспорт — черновик (RFD, цель v1); нет сообщений агента вне хода (cron) |
| **MCP** | инструменты, `tools/list_changed`, elicitation | все мозги | **да, для инструментов телефона.** Список держим стабильным, недоступность возвращаем ошибкой: мозги по-разному подхватывают смену списка посреди хода |
| AG-UI | события агент ↔ интерфейс, клиентские инструменты, прерывания «нужно подтверждение» | веб-фреймворки, не наши мозги | только как образец событий UI |
| A2A | агент ↔ агент | — | нет |
| OpenAI Chat / Responses | текст туда-обратно | Hermes, OpenClaw | запасной вариант «голая модель»: теряются сессии, инструменты, подтверждения |

Ни один стандарт не определяет **реплику мозга вне хода** (cron, напоминание, итог задачи, которую мозг делал на сервере). Это всегда наша часть.

Источники: [ACP](https://agentclientprotocol.com/protocol/overview), [ACP по WebSocket (RFD)](https://agentclientprotocol.com/rfds/streamable-http-websocket-transport), [MCP-over-ACP (черновик)](https://agentclientprotocol.com/rfds/mcp-over-acp.md), [Hermes ACP](https://hermes-agent.nousresearch.com/docs/user-guide/features/acp), [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview), [Claude Code channels](https://code.claude.com/docs/en/channels), [AG-UI](https://docs.copilotkit.ai/ag-ui/introduction).

## 4. Предложение: контракт сейчас, шлюз — когда понадобится второй мозг

Чтобы не строить лишней инфраструктуры заранее, делим на два шага.

**Шаг 1 (Ф1–Ф2).** Фиксируем **свой узкий контракт телефон ↔ мозг**, по смыслу совпадающий с ACP:
- сессия: открыть, продолжить, новая;
- реплика пользователя → поток ответа (`delta`, `final`);
- статусы и шаги (для гармошки);
- запрос разрешения с вариантами ответа (карточка П1);
- вызов инструмента телефона → результат;
- события вне хода (cron, итог серверной задачи);
- страница истории.

Первая реализация контракта — **плагин `android` в Hermes**, как и планировали. Отдельного сервиса нет. Инструменты телефона описываем в манифесте **сразу в формате MCP-схем**, чтобы их без переделки можно было отдать любому мозгу.

**Шаг 2 (когда захотим второй мозг или Hermes подведёт).** Выносим серверную половину контракта в **шлюз**:

```
Телефон ──WSS, наш контракт (ACP-подобный)──► Шлюз (наш, небольшой)
                                              ├─ вход, сессии, история, очередь, пуши
                                              ├─ MCP-сервер «телефон»: tools/call → телефон по WS,
                                              │  только при активной сессии
                                              └─ драйверы мозгов:
                                                   • ACP (stdio): hermes acp, claude-agent-acp, codex, gemini
                                                   • Claude Agent SDK: тонкий контроль подтверждений
                                                   • Hermes-плагин: если нужен его cron и мессенджеры
```

Приложение при этом не меняется: оно уже говорит на контракте. Драйвер Claude Code на Agent SDK — порядка 300–500 строк: `resume` сессии, MCP «телефон», `canUseTool` → наша карточка, поток SDK → наши события, cron — таймером в шлюзе.

**Почему не ACP напрямую с телефона.** Удалённый транспорт ACP ещё черновик, Kotlin SDK — snapshot. Наш тонкий фасад поверх WebSocket защищает приложение от изменений стандарта. Когда WebSocket-профиль ACP станет v1, контракт можно будет просто объявить ACP.

## 5. Что даёт и чего лишает каждый мозг

| | Hermes | Claude Code (Agent SDK / ACP) | Codex | OpenClaw |
|---|---|---|---|---|
| Качество агента на долгих задачах | среднее, зависит от выбранной модели | лучшее по отзывам | хорошее | как Hermes |
| Модели | любые, включая локальные | только Claude | только OpenAI | любые |
| Память | своя, сменные провайдеры | `CLAUDE.md`, авто-память, компакция; привязаны к рабочей папке | минимальная (`AGENTS.md`) | своя, частые жалобы |
| Cron и пуши вне хода | свои | нет постоянного: `/loop` живёт в сессии и истекает через 7 дней → делает шлюз | нет → шлюз | свои |
| Подтверждения | свои, через плагин | `canUseTool` / `request_permission` | есть | урезанно через ACP |
| Мессенджеры (Telegram-представитель) | из коробки, ~20 платформ | channels (research preview) или свой бот | нет | свои |
| Лицензия и оплата | MIT, свои ключи | Agent SDK — только по API-ключу; подписка — только через немодифицированный `claude` CLI | — | MIT; в марте 2026 — 9 CVE за 4 дня, вредоносные навыки в каталоге |

**При смене мозга теряется его память.** Чтобы это не было катастрофой, важное (заметки, «запомни», факты о пользователе) телефон и так шлёт событиями. Шлюз может вести копию таких событий и передать новому мозгу.

## 6. Трезвая оценка Hermes

Данные — клон от 28.09 и GitHub API на 17.10.2026.

**Плюсы:**
- открытый код (MIT), любые модели, в том числе локальные;
- мессенджеры из коробки, cron, профили и боты, сменная память;
- огромное сообщество: около 254 тыс. звёзд, около 4,5 тыс. участников;
- нативно говорит ACP и MCP — значит, его легко подключить и через стандарты.

**Тревожные сигналы:**
- **Темп изменений аномальный.** 19 тыс. коммитов за месяц, рекорд — 4 тыс. за день. Много коммитов от ботов и ИИ-соавторов.
- **Ломает плагины.** При «декомпозиции» сентября сдвинулись около 2 100 внутренних имён, плагины со старыми импортами отключаются, в v0.22 слой совместимости удалили. Документ совместимости прямо пишет: внутренние пути импорта — не стабильный API.
- **Бэклог не разбирается.** 33,7 тыс. открытых PR, 15,9 тыс. issue. За неделю создано 3,1 тыс. PR, принято 0,57 тыс.
- **Один ключевой мейнтейнер** (около 40 % коммитов за три месяца) и одна компания.
- **Код тяжело аудировать.** 2,1 млн строк Python; 29 файлов `hermes_state_*.py` в корне; монолиты по 6–8 тыс. строк.
- **Конкретные баги по нашей теме:**
  - сжатие по простою не срабатывает в режиме gateway (#79357);
  - heartbeat считается доставленным без доставки (#92837);
  - секреты профиля утекают в мультиплекс (#82936);
  - список навыков вставляется в каждый ход (#96455).
- **Стоимость.** Накладные 15–20 тыс. токенов на ход в режиме gateway; кэш промптов — только с v0.22 и по желанию.

**Вывод.** Ставить на то, что Hermes «сам станет лучше», рискованно: он быстро растёт вширь, но нестабилен как платформа. Как **первый** мозг он годится: у него есть всё, что нам нужно сразу (мессенджеры, cron, ACP, MCP), и он бесплатен по лицензии. Но архитектура должна позволять уйти от него за неделю.

Источники: `reference/hermes-agent/COMPAT_MANIFEST.md`, [релиз v0.22.0](https://github.com/NousResearch/hermes-agent/releases/tag/v0.22.0), issues #79357, #82936, #92837, #96455, #132817; [сравнение с OpenClaw](https://www.cometapi.com/hermes-vs-openclaw/), [оценка стоимости токенов](https://openclawdc.com/blog/hermes-agent-real-token-cost/) (вендорские, доверие ниже).

## 7. Как решаем, оставаться ли на Hermes

Меряем в Ф1–Ф2, параллельно гоняя тот же набор сценариев через Claude Code (Agent SDK или `claude-agent-acp`):

| Метрика | Порог, после которого переключаемся |
|---|---|
| Поломки плагина от обновлений Hermes за 6–8 недель | чаще раза в месяц |
| Доставка cron и сообщений вне хода | ниже 99 % |
| Задержка голосового хода, p50 / p95 | заметно хуже Claude Code на тех же сценариях |
| Токены и деньги за ход на 30–50 сценариях | дороже на 20 % и больше при той же модели |
| Успешность многошаговых задач (одна модель в обоих) | хуже на 20 % и больше |
| Помнит ли факты через 1, 7, 30 дней | хуже, чем память Claude Code |

**Что делаем уже сейчас, независимо от выбора:**
1. Hermes закреплён на стабильной SemVer-версии, обновления вручную, после прогона `hermes plugins compat` и наших тестов.
2. Плагин импортирует только документированный API платформ-плагинов.
3. Инструменты телефона описаны MCP-схемами.
4. Всё, что приложение отдаёт «в память», дублируется в журнал событий на нашей стороне.

## 8. Telegram-представитель при любом мозге

С Hermes он собирается штатно: отдельный профиль, режим наблюдения в группах, cron со сводкой (см. `Открытые_вопросы.md`, В5). С Claude Code это либо channels (research preview, нужен живой процесс), либо свой бот в шлюзе. Если представитель окажется главным сценарием Telegram, это довод держать Hermes хотя бы для этой роли, даже если основной мозг станет другим.
