# Экран, Гига Писарь, файлы — что можно добавить ассистенту (19.10.2026)

Исследование тремя субагентами: документация Android, исходники AOSP, правила Google Play, исходники `reference/giga-pisar-android` (0.2.11). Что не проверено на S24 — помечено.

## 1. Экран: роль помощника уже даёт чтение экрана

- При вызове системой (кнопка, жест) сессия получает `onHandleAssist(AssistState)`: дерево текста приложения под листом (`AssistStructure`), `AssistContent` (адрес страницы в Chrome, JSON-LD), и `onHandleScreenshot(Bitmap)`. Наши собственные `showSession(…, 0)` (уведомление, возврат из приложения) данных не получают.
- Галочки «Использовать текст с экрана» / «снимок экрана» — это `Settings.Secure.assist_structure_enabled` / `assist_screenshot_enabled`, по умолчанию включены. Снимка без текста не бывает.
- Блокируют: FLAG_SECURE (банки, пароли), Private Space, корпоративные политики, **и наша собственная активность на экране**.
- Система каждый раз показывает подсветку «помощник смотрит на экран» (для непредустановленного помощника) — вид на One UI не проверен.
- Данные — только в момент вызова, приходят асинхронно (до ~500 мс).
- Недоступно нам: «Обвести и найти», Visual Query, горячее слово, AppFunctions — системные.
- Direct actions (действия текущего приложения) — доступно, но почти никто не реализует; проверить пробником.

Сценарии: «сократи статью» (адрес + текст), «переведи экран», «ответь на это сообщение» (текст → черновик), «добавь в календарь с экрана», «позвони по номеру с экрана» (можно без мозга), «что это на экране» (снимок + зрение, дорого).

Как инструмент: захват при открытии листа в память (не на диск), стирание при закрытии; `screen_read` (текст, AUTO, но только по запросу мозга) и `screen_image` (снимок, ASK). Зависимость — системная галочка (как доступ к «Не беспокоить»), не разрешение. Ответы при отказе: выключено, приложение запрещает, лист открыт не кнопкой. Своя «чёрная» лента пакетов (банки, 2FA). Если инструмент выключен — `setDisabledShowContext`, чтобы система не собирала данные и не мигала. Пересматривает решение бэклога 17.10 «снимок экрана не нужен».

## 2. Гига Писарь

- Писарь — служба спецвозможностей: находит сфокусированное поле (`findFocus(FOCUS_INPUT)`), вставляет `ACTION_SET_TEXT` или вставкой из буфера; кнопка поверх — окно спецвозможностей; громкость вниз — запись.
- Правила Play для спецвозможностей: раскрытие + декларация с видео; **запрещено, чтобы ИИ сам выполнял действия через спецвозможности**; Android 16 скрывает «чувствительные» поля; Android 17 Advanced Protection отзывает такие службы (не проверено, вошло ли в релиз). Для Вахтёра — не брать (совпадает с бэклогом).
- Две копии модели: диск 2 × 225 МБ, память ~250–400 МБ на процесс (оценка). У Вахтёра модель грузится при каждом старте процесса (`App.kt`, `warmUp()`), у Писаря — при первой диктовке.
- Варианты синергии: (1) Писарь как библиотека — экономии нет; (2) общий файл модели через ContentProvider + проверка sha256 — одна загрузка; (3) **Вахтёр — системный распознаватель (`RecognitionService`)**, Писарь и любые приложения распознают через неё — одна модель в памяти; (4) мозг Вахтёра для Писаря через `ACTION_PROCESS_TEXT` / `ACTION_SEND`; (5) слияние — нет.
- Рекомендация: (3)+(2). Патч в Писарь (~200 строк, описан): интерфейс `Recognizer`, реализация через `SpeechRecognizer` Вахтёра, поиск модели у соседа, переключатель «Распознавание: своё / через Вахтёра».
- **Найдено попутно:** у Вахтёра `recognitionService = StubRecognitionService`. Пока Вахтёр — помощник, система может сделать его распознавателем по умолчанию, и чужие приложения с `SpeechRecognizer` получат ошибку. Проверить: `adb shell settings get secure voice_recognition_service`.
- «Напечатай в поле» мозгом — только через спецвозможности, нельзя по Play и против «Наружу — только руками». «Прочитай поле» — через чтение экрана (п. 1). Черновики — как сейчас, `ACTION_SEND` в мессенджер.

## 3. Файлы

- Реально: «Поделиться → Вахтёр» (любой файл, без разрешений), «Файл» в скрепке (`ACTION_OPEN_DOCUMENT`), одна выданная папка (`OPEN_DOCUMENT_TREE`; корень и папку Download выбрать нельзя), фото — MediaStore. `MANAGE_EXTERNAL_STORAGE` — Play не даст ассистенту. Файлы Telegram лежат в его закрытой папке — только через «Поделиться».
- Текст на телефоне: PDF — `PdfRenderer.Page.getTextContents()` с API 35 (на S24 есть; на Android 14 — страницы картинками); DOCX/XLSX — zip+xml без библиотек; до ~20 тыс. символов за раз, дальше по страницам.
- Инструменты: `files_find` (AUTO, имена), `file_read` (всегда спрашивать: карточка «Отправить мозгу: Договор.pdf, стр. 1–4, ~6 тыс. символов»), `file_open`/`file_share` (человек действует), `screenshot_last` (ASK), `storage_info` (AUTO).
- Порядок: «Поделиться → Вахтёр» + «Файл» с PDF/DOCX → последний скриншот → выданная папка. Не делать: фоновую индексацию, массовую отправку, «почисти загрузки».
